## 2. Сквозные тест-кейсы (Сценарии проверки)

### TC-01: Успешная запись клиента (Happy Path)
*   **Предусловие:** Открыт сайт, клиент не авторизован.
*   **Шаги:** 
    1. Нажать «Записаться онлайн».
    2. Выбрать услугу «Стрижка», мастера «Анна», дату «25 Окт» и время «14:30».
    3. Ввести имя «Тест» и телефон «79991234567».
    4. Поставить галочку 152-ФЗ.
    5. Нажать «Записаться».
*   **Ожидаемый результат:** Появляется экран успеха с деталями записи.
*   **Фактический результат:** Экран успеха появился, данные корректны.
*   **Статус:** Пройден ✅.

### TC-02: Проверка защиты от накладок (Альтернативный поток)
*   **Предусловие:** Мастер Анна уже имеет запись на 25 Окт в 14:30.
*   **Шаги:** Открыть окно записи, выбрать Анну и 25 Окт. Посмотреть на слот «14:30».
*   **Ожидаемый результат:** Слот «14:30» перечеркнут и неактивен (disabled).
*   **Фактический результат:** Слот заблокирован.
*   **Статус:** Пройден ✅.

### TC-03: Блокировка кнопки при отсутствии согласия (Негативный тест)
*   **Шаги:** Заполнить все поля, выбрать время, но **не ставить** галочку 152-ФЗ.
*   **Ожидаемый результат:** Кнопка «Записаться» остается серой и неактивной.
*   **Фактический результат:** Кнопка заблокирована.
*   **Статус:** Пройден ✅.

## 3. Фиксация логических дефектов (Bug Report)

В ходе экспертного аудита (до финальной доработки) были выявлены следующие дефекты:

| ID | Описание дефекта | Ожидание / Реальность | Серьезность | Приоритет | Статус |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **BUG-01** | **Конфликт перерыва и существующей записи.** Мастер закрывал время на перерыв, не учитывая, что в этот промежуток уже записан клиент. | **Ожидание:** Система предупреждает о конфликте.<br>**Реальность:** Перерыв создавался, в расписании появлялись две карточки на 14:30. | Высокая | Высокий | **Исправлено** ✅ |
| **BUG-02** | **Отсутствие маски и валидации ввода телефона.** В поле «Телефон» можно было ввести любые символы (буквы, знаки препинания). | **Ожидание:** Поле форматирует ввод в маску `+7 (___) ___-__-__` и блокирует ввод букв.<br>**Реальность:** Пользователь мог ввести буквы. | Средняя | Средний | **Исправлено** ✅ |
| **BUG-03** | **Неполный сброс формы при закрытии окна.** При закрытии модального окна записи очищалось имя и телефон, но выбранная дата сохранялась в памяти. | **Ожидание:** Все поля, включая выбранную дату, должны сбрасываться на значения по умолчанию.<br>**Реальность:** Дата оставалась прежней. | Низкая | Низкий | В бэклоге |
| **BUG-04** | **Отсутствие обратной связи при неактивной кнопке.** Кнопка «Записаться» блокируется без объяснения причин (нет подсказки). | **Ожидание:** При наведении должна появляться подсказка: «Заполните все поля и дайте согласие».<br>**Реальность:** Кнопка просто не нажимается. | Низкая | Низкий | В бэклоге |

## 4. Анализ качества по стандарту ISO/IEC 25010

*   **Функциональная пригодность (Полнота):** Прототип полностью покрывает сценарии записи, переноса и управления расписанием. *(Оценка: 5/5)*
*   **Удобство использования (Понятность, управляемость):** Интерфейс интуитивен. Расположение элементов снижает когнитивную нагрузку. *(Оценка: 5/5)*
*   **Безопасность (Конфиденциальность):** Требование 152-ФЗ выполнено: без явного согласия клиента кнопка записи заблокирована. *(Оценка: 5/5)*
*   **Сопровождаемость (Модульность):** В коде прототипа (HTML/JS) четко выделены функции рендеринга (`renderCalendar`, `renderTimeSlots`). Благодаря этому мы смогли быстро исправить баги BUG-01 и BUG-02, не переписывая весь код. *(Оценка: 4/5)*

## 5. Рекомендации по исправлению

1.  **Для BUG-01 (Выполнено):** В функцию `saveBreak()` добавлена проверка массива `appointments`. Теперь система блокирует создание перерыва, если на это время есть активная запись.
2.  **Для BUG-02 (Выполнено):** Внедрены обработчики `keydown` и `input` для поля телефона. Теперь ввод букв физически заблокирован, а цифры автоматически форматируются в маску.
3.  **Для BUG-03 (Рекомендация):** В функции `closeModal()` добавить полный сброс переменной `selectedDate` и перерисовку календаря (`renderCalendar()`).
4.  **Для BUG-04 (Рекомендация):** Добавить всплывающие подсказки (tooltips) для заблокированных кнопок.
